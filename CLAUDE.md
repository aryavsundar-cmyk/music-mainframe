# CLAUDE.md — Mainframe · Music

Working conventions for this repo. Mirrors how the sibling Mainframe apps run.

## Operator preferences
- **Terse responses.** No trailing recaps; the diff speaks.
- **Verify on preview before deploying.** Load the dev server (`.claude/launch.json` → `music-mainframe`, :5190), check console/network, check both themes, then push.
- **Comprehensive, multi-section commit messages** with a verification block.
- **Deploy = push to `main`.** Render auto-deploys from `render.yaml`. No other branches unless asked.
- **Never write Render's skip token in a commit message** — not even to describe it. Render skips the deploy if the latest commit message contains it ANYWHERE, body included; Sprint 24 sat undeployed for hours because its message explained how the archive job avoids deploys. Refer to it as "the skip marker". Only the archive workflow's own commits carry it. After every push, confirm `/api/health` reports the new sprint before calling it shipped.
- Commits end with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Design system is law
- `src/tokens.js` is the single source of truth. `src/tokens.css` is generated — never edit it.
- No hex values in components. Use the Tailwind utilities the tokens create (`bg-ground-1`, `text-ink-2`, `text-accent`, `border-line-1`, `text-money`…) or `var(--mm-*)`.
- Numbers go through `<Num kind>` / `utils/format.js`. Four kinds: money · count · pct · rate.
- One `primary` Button per view. Eyebrows numbered only in exports.
- Recording = gold, solid chain. Publishing = verdigris, dashed fan. Never "same diagram, different colour".
- Check `/design` after any token change; both themes. Every text role must clear 4.5:1 on ground-0…4 in both themes — `npm run test:contrast` enforces it, along with ink-ramp hierarchy, coloured text on its own tint, text on filled controls, and tokens.css being in sync. Never fix contrast in a component; fix the token.
- Lab explanations: plain-English definitions live in `data/glossary.js` (short · plain · worked example with real numbers · watch-out · related). Every execution step lists the terms it uses in its `terms` array, rendered by `components/lab/Concepts.jsx`; `/lab/glossary` is the searchable index. `npm run test:glossary` checks completeness, resolvable references, sentence length, and that no term is orphaned.

## Editions
- `src/editions.js` declares what each build contains. `full` is personal; `work` is the shareable research edition: Canvas, Money, Rights, Live, Market, Pipeline and Reference, no authored material, no Gamma.
- Exclusion happens at BUILD time. `vite.config.js` swaps the authored modules for stubs by RESOLVED path — an alias on the import string misses importers that spell the path differently, which is how a leak ships. Hiding a route is never enough: anything in the bundle is readable in developer tools.
- Every engine suite runs in BOTH editions: `npm run test:work` re-runs prospect, market and outcomes under `scripts/edition-loader.mjs` (a Node resolve hook applying the same swaps as the build), then `scripts/test-parity.mjs` compares the two. Tests assert edition-aware behaviour rather than duplicating: where authored material is absent, assert the app says so.
- Without the overlay, fit redistributes to the public components at `PUBLIC_FIT_WEIGHT` (declared in `utils/prospect.js`, currently 1.5) so tiers stay comparable. Never let a missing module silently lower every score.
- Adding anything authored (a new hypothesis set, rate, persona, case, internal link) means adding a stub and a swap, and a string in `scripts/test-edition.mjs`. `npm run test:edition` builds the work bundle and fails if private material appears, or if the public material disappears.
- Handing over source is a separate problem from shipping a bundle: `scripts/export-edition.mjs` (`npm run edition:work -- --out <dir>`) writes a standalone tree from an ALLOWLIST, deletes the private sources, materialises the stubs, rewrites the manifest/README/render.yaml, greps every copied file for private strings (deleting the tree on a hit) and builds it. Comments survive a source export though minification strips them from a bundle — the bundle test is not a substitute. `npm run test:export` runs it.
- `/about` (both editions) states provenance, and every count on it is measured from the data at render time — never asserted in prose.
- The work edition states what it is on screen and in exports (`src/editions.js` FRAMING, `components/EditionNotice.jsx`): an independent research tool, not a firm system of record, not advice, no client or personal data.
- Server: `MM_EDITION=work` serves `dist-work` and drops the Gamma proxy. `EMBED_ALLOW` sets `frame-ancestors` for embedding (SharePoint, say; deny by default). `ACCESS_USER`/`ACCESS_PASS` turn on basic auth, and never cover `/api/health` so the watcher keeps working.

## Code
- React 19 + Vite 7 + Tailwind 4 (CSS-first `@theme`; no `tailwind.config.js`) + React Router 7 + Lucide. JSX, not TS.
- Relative imports carry `.js` / `.jsx` extensions (Node ESM compatibility for scripts).
- Backend lives in `server/` at repo root, never under `src/`. `server/sources.json` (Sprint 5) stays JSON.
- Export formats are a TABLE, never an if/else chain: `RENDERERS` in `utils/download.js` and `WRITERS` in `scripts/generate-briefs.mjs` have one entry per format and throw on anything else. Sprint 20 shipped Word bytes named `.xlsx` because a fallback `else` rendered docx while the return value still reported a filename and a section count — verify the file, not the status line. `utils/framing.js` appends the research edition's framing section at both export entry points, so a forwarded document still states what it is.
- Five Forces (`/deals`): taxonomy in `data/forces.js` (transcribed from the spec — it drives classification; never restate a thesis elsewhere), engine in `utils/forces.js`, brief in `utils/forcesDocs.js`, UI in `components/forces/`. NO FORCE WITHOUT EVIDENCE: every tag keeps its evidence and `evidenceHolds` must pass for all of it. Calibration additions live in `EXTRA_TERMS` with a reason each; broad words are `generic` (lose ties), live nouns are `topical` (never high confidence). Place evidence only from a deal's SUBJECT and only from regional (tier 2–3) companies; resolve places by city before country code. News must pass `isMusic` (trade/live source, a music-native entity, or music words) before it can be evidence. Summary place names weigh 2 in deal records, 1 in scraped news. Deals always classify; events need 2 points and are otherwise declined WITH A REASON — never dropped silently. Direction is against the thesis as written. Every calibration false positive gets a test in `scripts/test-forces.mjs`.
- Evidence archive (`data/archive`, `server/archive.js`, `scripts/archive-news.mjs`, `.github/workflows/archive.yml`): the live feed forgets, the archive does not. Append-only — a story is recorded once (`utils/eventKeys.js`: id, URL, headline, shared by job and browser) and never rewritten; a no-op run must change no file. Archive raw music-relevant items and classify at READ time. Archive commits must never deploy (`[skip render]` + `buildFilter.ignoredPaths`); the server refreshes from the repository's raw files. Coverage is `coverageSince` = the day the archive started watching; any window reaching further back is a floor (`≥`, `windowComplete`) and weeks before it are hatched, never drawn as zero. Scripts that run the aggregator must `process.exit` — its sockets keep Node alive and a scheduled job would hang.
- Page exports: every page view goes through `utils/pageDocs.js` (`buildPageDoc`) and renders with `components/export/PageExport.jsx`. The builder NEVER re-filters or re-sorts — the page passes the rows it is displaying, in display order; a second copy of a filter drifts from the first. Every page export states its filters, sort, `shown of total` and capture time in section 1, exports an empty result rather than an empty file, and states any truncation (`MAX_TABLE_ROWS`). A page that is not a table exports what it is (flow stages, a feed snapshot with its staleness stated, the provenance statement). `describeFilters(params, defs)` gives filters reader-facing labels; `filterSentence` is the one-line form for documents with their own narrative. `npm run test:pagedocs` runs in both editions.
- Exports: `utils/brief.js` is the ONLY data builder; renderers (`briefText/Docx/Pptx/Xlsx.js`) consume it and never hard-code a section list. `briefXlsx.js` writes SpreadsheetML by hand over jszip: a table block becomes a sheet, stats and facts become the Summary sheet, and notes and citations become the Sources sheet so the limit notices travel with the numbers. A cell becomes numeric only when the string is a plain number — never guess at "$1,501K". The edition manifest decides which formats a build offers, and it must never advertise one the app cannot produce. Browser entry is `utils/download.js` (lazy-imports docx/pptxgenjs); Node entry is `scripts/generate-briefs.mjs`. Add a section to the builder, never to a renderer. Account plans, proposals, and sector decks (`utils/accountPlan.js`, `proposal.js`, `categoryDeck.js`) use the same block model; Gamma goes through `server/index.js` `/api/gamma/generate` (needs `GAMMA_API_KEY`). Rate card numbers in `data/rateCard.js` are indicative placeholders — never present them as A&M's actual rates.
- Data files: typed empty defaults, never `null`. Every record carries `asOf` + `sources[]`. A fact from the brief or memory that isn't cited gets `verify: true` and a dated note; a verification pass sources it or drops it. Never silently overwrite a sourced figure with a remembered one.
- Lab: numbers come only from the case's engine — `utils/valuation.js` (kind `valuation`), `utils/pmi.js` (kind `pmi`), `utils/abs.js` (kind `abs`), or `utils/carveout.js` (kind `carveout`); never hard-code a computed figure in UI or reviewer text — interpolate from the model. Run `npm test` after touching an engine or a case. New cases go in `src/data/cases/`, are registered in `cases/index.js`, declare `kind`, and carry `asPresented` (the flawed draft) and `benchmark` answers. Shared pitch/plan copy is case data (`copy`, `briefKpis`, `feeBase`, `weeks`, `question.test`), never literals in `PitchStage`/`PlanStage`. A new kind adds an engine, a `labEngines.js` entry, `*State.js` rows, Execute/Deliver stages, and a docs builder.
- The limits (`src/data/limits.js`) are the single source of truth: a match score means a buyer has done deals like yours, not that they are interested; an availability score is a prompt to do work, not a claim that an asset is for sale; a force tag says what an event is evidence of, not what will happen next. `LimitNote` renders them on every screen that shows a score, every export carries them, and `npm run test:outcomes` fails if a screen or document drops one. Never restate them inline — import them.
- Enrichment: `server/filings.js` resolves CIKs from SEC's own ticker map for every US-listed entity in `entities.js` (coverage tracks the table, never a hand-kept list), reads structured submissions, and serves `/api/filings` and `/api/enrichment/status`. Set `SEC_USER_AGENT` (e.g. `Name email`); SEC requires a declared agent, rate-limits hard, and 403s anonymous callers and some hosting providers — the connector then falls back to the CIKs seeded in `server/sources.json` and the UI states the reason. A connector that is down must say so in the UI, never silently score lower.
- Outcomes (`utils/outcomes.js`) are the operator's own local record and feed scoring: engagement raises access and decays after six months, a loss inside 90 days cools timing, "not now" parks an account out of the priority tiers until its date, and 90 quiet days marks it stale.
- Market modules: `utils/catalogScan.js` (demand side — holdings derived from sourced transactions and entity metrics, availability scored from owner behaviour, hold period, repayment dates, prior exits and sale-intent phrases in the live feed) and `utils/buyerMatch.js` (sell side — buyer profiles built ONLY from transactions on record, matched against a seller's brief). Never assert appetite a deal does not evidence, never claim an asset is for sale, and never tag a genre unless the word appears in the sourced text (`genreTags` keeps the matched phrase). Deliverables go through `utils/marketDocs.js` and `utils/prospectDocs.js` on the shared block model. `npm run test:market` covers both engines and all five documents.
- Prospecting: scores come only from `utils/prospect.js` and drafts only from `utils/outreach.js` — never hard-code a score, a tier, or a message in the page. Hooks live in `data/playbooks.js` (versioned; retire with a note), roles in `data/personas.js`. The module NEVER stores a named contact, sends anything, or leaves the browser: status, relationship strength, and notes are localStorage only. Run `npm test` after touching the engine or the data.
- Uptime: `npm run health` checks a running instance (answers · news cache not empty · last fetch recent · no fetch error) and exits non-zero with the reason; `.github/workflows/health.yml` runs it every 30 minutes and opens one `health`-labelled issue on failure. Locally, `npm run server:watch` supervises `server/index.js` and restarts it with backoff, giving up after five fast crashes so a real fault stays visible. Render restarts the single web service itself against `healthCheckPath`.
- Sibling apps (`~/Desktop/A&M/Agencies/am-intelligence-hub`, `…/programmatic-ecosystem`) are convention reference only. Reuse shapes (`PATTERNS-FROM-SIBLINGS.md` in the kickoff packet), never content. Never edit them from this session.
